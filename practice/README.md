# The practice kit — run the loop before it's your work

[EXAMPLES.md](../EXAMPLES.md) is the loop *read*; this is the loop *done*. Four fictional
Acme inputs, tuned so you hit the same beats — including the refusals, which are the
curriculum. About 60–90 minutes solo, in Claude Code or a Claude Project. Nothing here is
real, so every gate can bite at zero cost.

**How to run it:** hand each file to the named skill with the quoted ask. Don't smooth the
inputs — the traps are the lesson. If you're using ledgers, let the skills write one for
`acme-activation` as you go and ask the `conductor` "where are we?" between steps.

| Step | Hand over | Say | What you should experience |
| --- | --- | --- | --- |
| 1 | [acme-research.md](acme-research.md) | "What's the real pain here?" | `research-to-pain` crowns the activation pain on triangulated signal — and **refuses** the VP-consensus item and the dashboard feature request. Notice *why* each is refused. |
| 2 | [acme-prd.md](acme-prd.md) | "Turn this into an IA" | `prd-to-ia` passes (the PRD states its goal *and* pain) and returns an **exclusions list** — watch the billing and GTM cruft get named, not silently dropped. |
| 3 | the pain + IA | "Write the brief" | `brief-from-pain` **refuses first**: no success criteria. Set the bar (34% → 50% day-7 activation in 8 weeks, say) and ratify it — now it writes, ending with "what good looks like." |
| 4 | the brief | "Write a v0 prompt for this" | `brief-to-prompt` emits one prompt + a **Discernment checklist**. Read the checklist before anything else — it's what you inspect, not admire. |
| 5 | [acme-prototype.md](acme-prototype.md) + the brief | "Is this ready for review?" | `prototype-triage` **FAILs it with a gap report**: the criteria fraction, the gap to close first, the ranked punch list. No human review spent. Regenerate the prompt with the punch list; describe the fixed prototype; re-triage → PASS. |
| 6 | the passing prototype + a test result you invent honestly (e.g. 5 of 6 completed setup, baseline 2 of 6) | "Write the spec" | `prototype-to-spec` writes the spec **with a Validation Record** — try it once *without* the test result and watch it refuse and hand you the smallest test instead (that's `validation-plan`'s territory). |
| 7 | [acme-analytics.md](acme-analytics.md) + the spec | "Did it work?" | `outcome-readout` renders **partial** — 49% against a 55% bar, real movement honestly short — **and reads the guardrail beside it** (invite acceptance 54% vs the ≥62% it was ratified to hold: broken, and it says so). Then it hands you the next Intent input. The loop closes. |

**What you just practiced** (the 4Ds, if you use that frame): *delegation* in what each
skill took off you, *description* in the brief and prompt, *discernment* in the checklist
and triage, *diligence* in the bar, the record, and the readout that refused to round 49
up to a win.
